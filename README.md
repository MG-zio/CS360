# CS360
Work from my Mobile Architecture &amp; Programming class at SNHU.

- Briefly summarize the requirements and goals of the app you developed. What user needs was this app designed to address?

    * The required aspects of the event-tracking application were a login page, a page with a grid that displayed events, and the ability to add, remove and edit events in the grid. The application also had to use SMS alerts for events and needed to use databases to store login information and the events themselves. The user need the application was made to address was storing important dates, details about them, and notifying users close to when they occur.
- What screens and features were necessary to support user needs and produce a user-centered UI for the app? How did your UI designs keep users in mind? Why were your designs successful?
    * I decided that I wanted a dedicated login page, an event grid page, a separate event creation page, and a settings page. This was close to the bare minimum number of screens that were necessary, but if I had more time in the future, I would have changed it so that the event creation page overlaid itself on the event grid page which would reduce the number of screens even more. The design kept users in mind by having a simple interface that had no unneeded information displayed. Everything could be comprehended at a glance, and the user interface experience was consistent across every page.
- How did you approach the process of coding your app? What techniques or strategies did you use? How could those techniques or strategies be applied in the future?
    * I tried to make my code modular and used functions that could be called from multiple places in the future and maintained separately. For example, in my main event grid screen I added a function that updated the grid which I could call whenever changes were made to the grid. I also made sure that the names for my variables were easy to understand so that my code was easily readable. I tried to avoid over commenting, but any time there was code that was not obvious in what it did I made sure to document it with a comment. I try to use these techniques on all my projects and additionally add function signatures when it makes sense.
- How did you test to ensure your code was functional? Why is this process important, and what did it reveal?
    * There were many times when my code failed to execute and I needed to use different tools to understand why. Print statements were something I used a lot to understand where things were going wrong and stepping through the code and putting in code breaks also helped me find fatal issues. I wrote tests that checked normal and edge cases that could cause issues. This process and the tests I created were important to understand how the code works and to refer to in case major changes are needed in the future so that they can be checked again.
- Consider the full app design and development process from initial planning to finalization. Where did you have to innovate to overcome a challenge?
    * I think the biggest innovation was the adaption of a card into an element of a RecyclerView. Innately I could have imported data into the RecyclerView from the database, but that would not have looked the best and might not have worked if I needed a graphic or something else on it in the future. By making an Event card in XML that could populate the RecyclerView the application was more future proof and looked a lot better in my opinion. It was hard to write the adapter class, but it was worth it in the end when the XML I made looked so good as squares in the grid.
- In what specific component of your mobile app were you particularly successful in demonstrating your knowledge, skills, and experience?
    * I think my solution to the event creation page was the most personal and showcased my abilities the best. The class had to be very modular with the ability to create a new event, edit an old event, or delete one entirely. Keeping the editing and creation on the same page made the app feel consistent and it is part of the reason I think it came out so well.
